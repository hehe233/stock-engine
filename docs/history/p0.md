## 目标

让一个前端开发者能够独立追踪一次请求：点击样本的「分析」按钮，经过 FastAPI、SQLAlchemy 和 LangGraph，得到可再次打开的报告。

第一版不以选股收益为验收标准。它优先验证模块职责、数据一致性、可运行性与学习体验。

## 手动验收

1. 启动后打开首页，确认明确标注「演示数据模式」，不是实时市场。
2. 搜索 `DEMO001`，只显示「样本·算力一号」。
3. 点击分析，得到 `91.94/100` 规则热度分和四个执行步骤。
4. 在报告中确认行情时间、快照 ID、规则版本与风险说明。
5. 刷新浏览器，报告仍可读取。
6. 返回工作台手动刷新，采集时间变化，固定样本行情时间不变。
7. 打开历史报告，原有结果与快照 ID 不变。
8. 搜索不存在的代码，显示空态；停止后端后刷新页面，显示可重试的错误。
9. 调小浏览器宽度，顶部导航可用，行情表在自身区域横向滚动。

## 本版刻意延后的内容

- **真实行情与盘口**：没有用户提供的数据源权限，不能把公共抓取接口或样本冒充生产实时数据。
- **自主 Agent / LLM**：P0 是确定性工作流。P1 增加模型决策、工具调用、条件分支、预算与输出校验。
- **妖股概率**：需先定义预测标签并完成样本外概率校准，当前只提供透明的规则热度。
- **龙虎榜、连板梯队、资金流向、持仓**：在真实行情与披露时间模型稳定后实施。
- **近十年妖股一览与规律**：需要构建可核验的历史数据库，包含失败样本，再生成统计。
- **Redis / Celery / SSE**：P0 分析计算很短，先使用普通请求；长耗时模型任务出现后再引入队列与流式进度。
- **回测 / LightGBM / Parquet / DuckDB**：在历史数据层落地时加入，避免第一版安装大量未使用依赖。

## 后续顺序

**P1：真实行情 + LLM 工具调用。** 选定授权数据源，接入交易日历、数据新鲜度与供应商异常处理；模型只调用受控工具，输出经 Pydantic 校验；加入持久化检查点和任务状态。

**P2：研究功能。** 完成连板梯队、龙虎榜、资金口径、持仓与历史案例库。

**P3：量化验证。** 加入可成交回测、失败样本、滚动训练、概率校准和持续监控。

## 质量边界

可运行和已测试不等于保证无 bug。以可重复的验收命令、测试覆盖的行为与已知局限报告质量；不对未验证的数据库、真实行情接口或部署环境作成功承诺。
