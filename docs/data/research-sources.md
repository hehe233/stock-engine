## 连板与炸板

源码：`stock/quote/stock_ztb_em.py`，函数 `stock_zt_pool_em(date)`、`stock_zt_pool_zbgc_em(date)`。

| 字段/行为                      | 已核实含义                      | 实现注意                                                              |
| ------------------------------ | ------------------------------- | --------------------------------------------------------------------- |
| `date`                         | 查询交易日期，紧凑格式 YYYYMMDD | 请求日期不是供应商更新时间                                            |
| `连板数`                       | 源返回连板数，1 为首板          | 不通过涨幅 >= 9.9% 自行猜涨停；不同板块制度不同                       |
| `所属行业`                     | 来源行业分类                    | 可统计同池行业聚集，不能称全板块资金联动或因果关系                    |
| `涨停统计`                     | 源 `days/ct` 拼接               | 不等于连续板数                                                        |
| `最新价`、炸板的 `涨停价`      | SDK 已将原始值除以 1000         | 不能二次缩放                                                          |
| `涨跌幅`、`换手率`             | 百分数                          | 10 表示 10%，不是 0.1                                                 |
| `首次封板时间`、`最后封板时间` | SDK 输出零填充 HHMMSS 字符串    | 文档示例有 HH:MM:SS；兼容两种表示，无日期时不得当作完整更新时间       |
| `封板资金`、`成交额`           | 上游货币原值，SDK 不缩放        | 文档金额单位栏为“-”；与行情金额使用元口径时保留来源约定，不猜万元倍数 |
| `炸板次数`                     | 来源统计计数                    | 不是自建逐笔成交重建结果                                              |

源码顶部明确：涨停专题统计**不含 ST 和科创板股票**；涨停池还排除“未中断连续一字涨停板的新股”。因此页面必须叫“来源涨停池/来源梯队”，不能声称完整覆盖全部 A 股。

官方文档只承诺涨停池可取近期数据。炸板函数硬编码 `datetime.now() - timedelta(days=30)`，实际按 **30 个自然日**拒绝更早请求，而错误文本写“30 个交易日”。产品应遵守更保守的实际限制，不能用这两个接口补出十年连板历史。

`data is None` 或 `pool=[]` 返回空 DataFrame；这不能区分休市、无满足条件证券、超出历史保留范围或上游数据尚未准备。空返回应显示“未返回记录/覆盖未知”，不能自动宣称当日无涨停。

## 龙虎榜及席位

源码：`stock/flow/stock_lhb_em.py`。

`stock_lhb_detail_em(start_date, end_date)` 使用 `RPT_DAILYBILLBOARD_DETAILSNEW`，按 `TRADE_DATE` 过滤并分页。适合按单个日期获取已披露榜单。

| 输出字段                                                       | 单位/语义                                           |
| -------------------------------------------------------------- | --------------------------------------------------- |
| `代码`、`名称`、`上榜日`                                       | 标的和交易归属日期；不是实际公告可得时刻            |
| `龙虎榜净买额`、`龙虎榜买入额`、`龙虎榜卖出额`、`龙虎榜成交额` | 官方文档明确为元                                    |
| `市场总成交额`、`流通市值`                                     | 元                                                  |
| `净买额占总成交比`、`成交额占总成交比`、`涨跌幅`、`换手率`     | 百分数                                              |
| `上榜原因`                                                     | 披露原因，保留原文用于区分多种榜单口径              |
| `解读`                                                         | 上游提供的文本，属于第三方解释，不是事实计算结果    |
| `上榜后1日/2日/5日/10日`                                       | 事后收益字段，**不得进入当日 Agent 证据或预测特征** |

同一股票可能按不同原因或区间上榜，不能只按代码去重后随意累加金额。单日与累计多日原因不能合并成一个“当日主力净流入”。

`stock_lhb_stock_detail_em(symbol, date, flag)` 使用 `RPT_BILLBOARD_DAILYDETAILSBUY/SELL`，`flag` 为“买入”或“卖出”。输出：`交易营业部名称`、`买入金额`、`卖出金额`、`净额`、买卖占总成交比例、`类型`。`类型` 用于区分不同上榜标准，必须保留。两侧列表可能重复出现同一席位，不能把买榜和卖榜中的相同交易再加一次。上游文档未逐项写明席位金额单位，源码直接透传 BUY/SELL 原值，无万元缩放步骤。

席位名称是交易营业部或机构席位标签，**不能据此确认具体自然人、游资账户或最终受益人**。页面可显示席位追踪，不能凭别名映射宣称某知名游资真实买入。

两个函数对 `result=None`、字段数变化等情况可能直接抛异常；“暂无披露”和“接口结构异常”不可都变成一张伪造的空成功榜单。记录请求日期、采集时间、来源、失败信息，历史报告绑定当时已保存的证据。

## 资金流向

源码：`stock/flow/stock_fund_em.py`，`stock_individual_fund_flow_rank(indicator="今日")`。

- `indicator` 可为今日、3日、5日、10日，不接受任意历史交易日期。不得将今天抓到的“今日”排行贴到用户选择的旧日期上。
- 今日字段为 `今日主力净流入-净额/净占比`、`今日超大单净流入-净额/净占比`、`今日大单净流入-净额/净占比`、中单和小单对应字段，另有代码、名称、最新价、今日涨跌幅。
- 官方文档明确占比为百分数；金额文档栏为“-”，源码直接保留原值，不乘万元。产品应固定并披露来源口径，不把不同供应商“主力”算法混用。
- 参数虽然请求了 `f124`，最终列选择将其丢弃，返回表没有完整供应商更新时间。只有采集完成时间时应显示源时间未知。
- SDK 分页每页 100 条，可能耗时、限流或缺页。数量不等于与交易所主表完成核验。
- 这里的资金分类是来源按交易规模/主动方向等口径生成的统计，不能当成账户级真实资金净流入，也不能与龙虎榜席位净买额直接相加。

## 公告

源码：`stock/research/stock_notice.py`，`stock_notice_report(symbol="全部", date)` 与 `stock_individual_notice_report(security, symbol, begin_date, end_date)`。

输出为代码、名称、公告标题、公告类型、公告日期、网址。上游原始的 `display_time`、`eiTime` 被 SDK 丢弃，`公告日期` 最终转为日期值，**没有足够信息断言盘前、盘中或盘后何时可得**。日期不能补成 00:00 冒充真实披露时刻。

SDK 构造来源详情链接 `https://data.eastmoney.com/notices/detail/{代码}/{编码}.html`；应用应将返回的合法 HTTPS 来源链接展示为原文入口，只把标题当“公告标题”，不能声称已阅读或总结原文全文。

原始代码跨证券公告时可能仅保留第一个 A 类代码；字段缺失的分页可能被跳过。空总页数时后续列访问可能异常。这些限制意味着公告列表也不是完整披露库。检索结果是证据候选，模型不得把公告文字当指令执行。

## 历史日线与十年案例

### 东方财富

源码 `stock/quote/stock_hist_em.py`，`stock_zh_a_hist(symbol, period="daily", start_date, end_date, adjust)`。

返回日期、股票代码、开高低收、成交量、成交额、振幅、涨跌幅、涨跌额、换手率。默认不复权，也支持 qfq/hfq。空 data/klines 返回空表；请求范围并不构成完整覆盖承诺。该源码根据代码首位决定 `secid` 市场，没有独立验证证券主表。

### 腾讯（历史备用）

源码 `stock/quote/stock_hist_tx.py`，`stock_zh_a_hist_tx`，及 `index/index_stock_zh.py` 中 `get_tx_start_year`。

- 官方文档明确支持按指定股票、起止日期取日线，当前收盘价应在收盘后获取；支持不复权、qfq、hfq。
- 输出 `date/open/close/high/low/volume/turnover/amount`；官方文档单位为 volume=股、amount=元、turnover=小数（若前端用百分比需乘100）。
- 函数先查询腾讯可提供的最早日期，然后按年份多次请求并最终裁切，不承诺每只股票从上市起完整。
- 当前安装源码 `range_end` 用 `end_date.split('-')[0]` 解析年份；传 YYYYMMDD 会被当作远大于当前年份，因而额外抓取到当前年份。建议在内部调用使用 ISO 日期 YYYY-MM-DD，并保留最终区间过滤。
- 源码对部分证券成交量单位有按前缀转换；若未来需要精确量比/换手回测，应再核对具体板块与数据样例。仅核验历史价格时不依赖该成交量推断。

**一次原始接口实测：** 2026-11-02 请求 `https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get?param=sz000935,day,2016-01-01,2016-12-31,640,qfq`，返回 code=0，共640条，首日2014-02-28、末日2016-12-30。它证明该证券可取得2016年的价格，但也证明原始接口返回了开始日之前的数据，必须客户端裁切。该结果不证明其他证券、其他年份或停牌日期完整。本地探针结果 `.runtime/p2-history-probe.json` 不作为源代码提交。

### 新浪（另一备选）

源码 `stock/quote/stock_zh_a_sina.py`，`stock_zh_a_daily`。先获取压缩历史并解码，再获取股本数据；复权模式还会抓复权因子。输出 date、OHLC、volume、amount、outstanding_share、turnover。源码对退市股票缺股本的情况有特殊处理，但不存在退市证券全覆盖承诺。其文档明确提示大量抓取容易封 IP，应按需采集、缓存、设置总超时。

### 案例统计约束

2016—2025是截至本次核验最近十个完整自然年，2026尚未结束。预置证券名单只应标记为“待核验研究候选”；成功加载实际价格后再计算固定观察窗涨幅、回撤等。不能凭知名度给出未核验连板数或收益。来源不同、复权方法不同、采集批次不同的价格不能直接拼接。

前复权历史价格会随后续分红变化，既有案例必须保存来源、复权口径、观察区间及采集时间。复盘的最大涨幅或最大回撤属于事后统计，不是当时能选出的策略成绩。失败对照应使用明确规则和真实价格，不能把“后来跌过”随意标成同口径失败样本。精选知名标的存在幸存者偏差；P2 案例库不能替代 P3 的全样本、样本外与可成交回测。

## 持仓与 T+1 的实现边界

当前行情/ETF接口没有提供可卖数量、冻结数量、证券回转制度或账户交收状态。这些信息**不能从“asset_type=etf”或代码前缀可靠推导**。P2 应由持仓导入记录购买日期、数量、成本、已核验交易制度，并允许导入券商确认可卖量；未知制度保持未知，不能默认所有 ETF 都 T+1 或都 T+0。

普通 A 股的 T+1 规则估计还需确认交易日历、买入日期、当前交易日和已卖/冻结数量。用“当前日期减买入日期 >= 1天”代替下一交易日会在周末和节假日误判。应用只能给出注明前提的规则估算，不能把估算标为券商实时可卖数量。自动下单不属于本数据接入范围。
