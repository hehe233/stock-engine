# 数据与量化开发规范

修改行情标准化、研究证据、持仓、历史统计或 `apps/api/app/quant/` 时阅读本文件。字段和算法参数见 [P3](../../modules/quant.md)，公开源口径见 [P2 数据源核验](../../data/research-sources.md)，这里约束修改与验证方式。

## 数据可追溯性

- 新来源明确证券范围、单位、复权口径、源日期/可见时间、采集时间和缺失情况。`quote_time`、批次 `as_of`、`fetched_at` 分别使用；未知源时间不以采集时间补造。
- 公开和演示模式隔离；不可变批次、新数据版本及 SHA-256 组成审计依据。修订数据创建新版本，不覆盖已被任务和报告引用的内容。
- 缺价格、成交量、交易制度或未来标签时保持未知，不能填零后当作真实观测。免费源采集成功不代表全市场覆盖核验成功。
- 模型读取提交时已可见的冻结证据；事后字段与尚未完成标签窗口的实验摘要不能进入当时证据。

## 研究与持仓

- 热度分是规则，历史窗口是描述统计，概率来自量化实验，文字解读来自模型；接口和 UI 名称须体现各自含义。
- 连板、涨停和资金口径沿来源定义，不能用固定涨幅阈值猜测制度或账户身份。
- 金额与成本沿用 Decimal，持仓汇总按证券处理；缺行情时估值/盈亏未知。T+1 使用交易日历，ETF 制度需明确，不能仅凭类别推断可卖数量。
- 精选历史案例保留选择偏差和复权限制；新增统计须说明样本、窗口、分母、缺失与重叠，不能把事后挑选结果包装成胜率。

## 训练与校准

1. 明确预测目标、信号日、标签结束日及数据可见时点；特征仅使用信号时刻已可用的信息。
2. 同日期证券进入同一分区；训练、校准和测试按时间前推，跨分区的未来标签与迟到数据按现有 purge 规则剔除。
3. 校准、阈值选择和调参使用相应历史分区；测试集仅评估。保留原始预测、校准预测和基准，指标变差也如实报告。
4. 记录数据/代码哈希、依赖版本、特征版本、参数、种子和模型产物；数据不足明确失败，不合成公开样本凑门槛。

## 成交与产物

- 标签收益区间和实际交易区间分别描述。撮合沿用下一交易日开盘及实际制度字段，核对 T+1、整数手、现金、费用、滑点、成交量上限、停牌和涨跌停。
- 未知制度、缺价、未处理公司行动或卖出受阻按保守规则拒绝/延后并记录原因；剩余仓位与不完整估值明确展示。
- 实验只访问服务端确定的产物目录；查询使用参数绑定，不接受用户 SQL、任意文件路径或 pickle 模型。读取前验证对应哈希。
- 产物路径、完整性、分页和写入使用 `quant/artifacts.py`。service 在文件就绪后提交元数据；失败只清理已确认未引用的本次版本，提交结果不确定时优先保留。异常/强杀的区别见[产物发布边界](../../modules/quant.md#产物发布与故障边界)，修改此路径运行 `test_artifact_publication.py`。
- worker 中断、取消与超时有明确状态；量化任务不借用 LangGraph checkpoint，也不自动转成实盘订单。

## 完成标准

按影响运行 `test_p2.py` 或 `test_quant.py` 中相关测试：未来价格扰动不改变过去特征、时间切分和可见性、缺失与公司行动、成交拒绝、估值完整性、文件篡改、模式隔离与中断。修改导入或报告 UI 时补相关浏览器验证。报告说明数据范围和未核验覆盖，测试通过不能证明实盘有效。
