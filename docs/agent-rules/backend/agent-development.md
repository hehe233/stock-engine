# Agent、任务与流式开发规范

适用于 `apps/api/app/agents/`、`jobs/service.py`、worker 的研究任务管理以及前端 `components/agent/`。事件名称与 payload 的唯一说明入口为 [Agent 流式输出](../../modules/agent-stream.md)。

## 修改前追踪

先从[源码导航](../../architecture/source-map.md)追踪本次相关链路，确认任务 ID、快照、模型配置版本、冻结证据、thread_id、lease_owner、attempt、事件 ID 和报告 ID 的角色。区分任务执行状态、图检查点、持久化事件、报告归档和抽屉展示状态。

## 图与工具边界

- 节点读取 state，返回局部更新；入口经 Pydantic 校验。串行 trace 的追加方式不能直接用于并行分支，并行写共享字段须定义合并语义。
- 规则计算、概率预测和语言模型解释分工保持明确；模型不能改写程序计算的热度分或生成无实验依据的概率。
- 工具只访问允许的冻结证据；新增工具明确输入 schema、输出、权限、数据来源、预算与缺失处理。保持最大轮数、请求超时和总任务超时。
- 模型输出须完成 JSON、结构与证据引用校验；部分参数只作草稿。未知 evidence_id、截断 JSON 和无效结构不能归档为成功报告。
- 模型没有返回公开思考字段时显示缺失说明，不推测隐藏推理。工具轨迹和节点记录只代表程序实际执行。

## 任务与恢复

- 提交绑定当时的快照、模型配置和研究上下文；持仓只有显式选择才进入证据。执行中不偷偷改读“最新”批次。
- 条件领取与租约校验保护状态写入；取消、超时、过期恢复和用户重试分别保持既有语义。
- 同一任务使用既有 thread_id 恢复 checkpoint；恢复已有状态使用当前实现的空输入路径，不能重传初始 state 导致已完成节点重跑。
- 最终报告、证据与成功状态沿用同一事务提交。远程模型计费与本地事务无法原子提交，恢复验证要观察重复调用，而不是承诺绝不重复。

## SSE 与 UI

- `run_job.py` 保存事件，路由输出 `progress`；任务终止且剩余分页全部排空后才发送 `done`。保留 Last-Event-ID / after 续传行为。
- 数据库事件 ID 用于顺序和去重，attempt 区分重试，block_id / call_id 配对模型块与工具调用。新事件兼顾历史任务回放。
- `useJobStream` 批量提交增量；终态再刷新相应查询。避免每 token 发状态请求或重建完整展示树。
- 缓存失效调用 `features/jobs/queries.ts` 的领域规则；重复终态与 done 避免重复刷新。跨端语义样例在根目录 `tests/fixtures/agent-replay.json`，由后端事件回放测试和前端投影/浏览器测试共用。
- 展示组件消费已有状态；断线可重连，空事件不能推导任务完成。抽屉关闭不影响订阅；订阅卸载清理连接和计时器。
- 报告草稿与已归档结果分别展示；重试时上次未完成块应呈现中断，历史事件不能被新一轮静默覆盖。

## 完成标准

涉及的行为至少覆盖对应场景：正常完成、无思考字段、分片工具参数、重复事件、分页排空、断线回放、失败/取消/重试、无效引用与截断输出拒绝归档。后端优先运行相关 `test_agent_stream.py`、`test_p1.py`，前端消费变化运行 `agent-stream.spec.ts`；具体命令见[全局规则](../global.md)。
