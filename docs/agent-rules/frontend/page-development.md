# 页面开发规范

适用于 `apps/web/src/pages/`、路由和页面数据流。验证命令见[全局规则](../global.md)，外壳交互见[工作区界面](../../modules/ui-workspace.md)。任务提示词见[前端提示词](prompts.md)。

## 路由与页面归属

- 路由在 `apps/web/src/main.tsx` 的 `createBrowserRouter` 注册；新建或迁移页面采用 `pages/页面名/index.tsx`，自身样式放在 `index.less`，沿用命名导出。当前页面均已采用目录入口，列表与详情分别组织；首页直接加载，其余路由按需加载，加载边界放在路由内容内以保留外壳和鉴权。新增导航入口同时检查 `App.tsx` 的分组、活动态和移动导航。
- `App.tsx` 是持久外壳，子页面由 `Outlet` 展示；鉴权沿用 `AuthGate`。侧栏宽度、折叠和抽屉开关不应重挂载任务页或重建 SSE。
- 页面协调查询、mutation 和展示。可复用展示拆到 `components/`；领域计算保留在后端对应模块。仅因页面变大不新建第二套路由或状态体系。
- 生产为 Vite 静态产物；新增深链接要考虑刷新时的 SPA fallback，开发代理不能代表生产代理已配置。

## 请求与状态

1. 普通 JSON 请求在 `api/` 对应领域文件扩展，通过 `api/http.ts` 的 `request` 统一前缀、错误与超时处理；同步维护前端类型和后端响应 schema。
2. 服务端状态使用 TanStack Query；query options、key 与跨视图失效规则统一放在 `features/<领域>/queries.ts`，页面调用领域 helper。key 包含筛选、分页和实体 ID；变更同时检查列表、详情及关联视图。缓存行为回归使用 `e2e/query-contracts.spec.ts`。
3. 输入草稿、筛选和展示开关留在组件；需要持久化的界面偏好沿用已有模式，浏览器存储失败不能阻断研究流程。
4. SSE 通过 `components/agent/useJobStream.ts`，不为同一任务另起轮询/事件实现；订阅、计时器和监听器有清理路径。
5. 认证通过现有后端 cookie 与 `AuthGate` 流程；模型密钥只提交给后端设置接口，不进入前端持久化或构建变量。

## 可观察状态与完成标准

- 首次加载、刷新中保留旧数据、空结果、查询失败和 mutation 失败有对应反馈；失败不能伪装成成功空数组。
- 数据缺失显示占位并保留原因。金额、时间复用 `lib/format.ts`；行情源时间和系统采集时间分别展示。
- 涉及研究操作时核对提交的证券、快照、模型与显式持仓选择；切换筛选或刷新数据不能悄悄改变已提交任务的依据。
- 新增或修改页面完成后，验证直达/刷新、导航返回、主要操作、错误恢复与窄屏；涉及公共外壳时确认正在进行的流式输出保持连续。
